## Writing and documentation focus

- **Developer-facing documentation:** API references, integration guides, authentication flows, and technical explanations.
- **Operational documentation:** SOPs, troubleshooting guides, runbooks, change-control procedures, and recovery guidance.
- **Technical content:** Research-driven articles, educational explainers, and training-oriented scripts.
- **Documentation quality:** Audience analysis, source verification, practical testing, consistent terminology, and Git-based review.

## Working approach

I start with the reader's task, document prerequisites and decisions, and identify how a user can verify the expected result. For lab-based projects, I record what actually worked, what failed, and what remains untested rather than presenting a demonstration as a production-ready solution.
